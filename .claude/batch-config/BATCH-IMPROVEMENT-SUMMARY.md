```
✅ 개선 후: "퇴직금·정의·종류 개요"
```

### 2. 제목 구조 표준화
**적용 패턴:**
```
[베이스 2단어] + [롱테일1·롱테일2·롱테일3] + [행동 유도어]
```

**예시:**
- `DB형 퇴직금·수령·전환 절차` (베이스 "DB형 퇴직금" + 롱테일 "수령·전환" + 행동어 "절차")
- `퇴직금·미지급·청구 기한 지연이자` (베이스 "퇴직금" + 롱테일 "미지급·청구 기한·지연이자" + 암시적 행동어)

### 3. 단어 정리

#### ❌ 제거된 단어
| 단어 | 이유 | 예시 |
|------|------|------|
| "안내" | 너무 일반적, SEO 약함 | ~~"절차 안내"~~ → "절차 확인" |
| "기준" | 가중치 없음 | ~~"기준 확인"~~ → "방법 절차" |
| "가이드" | 블로그식, 웹마스터 패널티 | 제거 |

#### ✅ 사용된 행동 유도어
| 행동어 | 사용 빈도 | 예시 |
|--------|----------|------|
| 방법 | 최다 | "신청 방법", "계산 방법" |
| 절차 | 높음 | "신청 절차", "청구 절차" |
| 계산 | 높음 | "계산 방법", "계산 도구" |
| 확인 | 중간 | "기한 확인", "조건 확인" |
| 신청 | 중간 | "신청 방법", "신청 절차" |
| 청구 | 중간 | "청구 절차", "청구 기한" |
| 받기 | 낮음 | "환급 받기", "지급 받기" |
| 대응 | 낮음 | "대응 방법", "미지급 대응" |

### 4. Keywords 엄격한 검증

**규칙:**
- 정확히 5개 고정
- 단일 단어 또는 2단어만 (3단어 이상 금지)
- 스팸 키워드 제거
- 소제목과 겹치지 않도록 변형

**검증 예시:**
```markdown
제목: "DB형 퇴직금·수령·전환 절차"

Keywords (정확히 5개):
1. DB형 퇴직금 (2단어 - 베이스 키워드)
2. 퇴직금 수령 (2단어 - 타이틀 "수령" 포함)
3. 연금 전환 (2단어 - 타이틀 "전환" 포함)
4. 수령 방법 (2단어 - 행동어 "절차" 대체)
5. 전환 절차 (2단어 - 직접 매칭)
```

### Frontmatter 필수 사항
```yaml
---
title: "롱테일 제목 (5개 키워드 중간점 연결)"
description: "~해요 패턴 (알아봅니다 금지)"
category: "근로/노동"
keywords: [정확히 5개, 단일 또는 2단어만]
author: "머니위키 에디터"
updateNote: "2026년 1월 기준"
lastUpdated: "2026-01-22"
datePublished: "2026-01-22"
summary: [배열 3줄 고정]
sources: [클릭 가능한 URL]
faq: [3개 고정, 소제목과 안 겹침]
---
```

### 본문 구조
- **기승전결**: 명확한 이야기 흐름
- **섹션당 4문장 이상**: 충분한 설명
- **구어체**: "~이에요", "~해요", "~하죠" 필수
- **테이블**: 2개 이하 (필요시만)
- **내부링크**: 3개 이상 (`/w/슬러그` 형식)
- **출처**: 본문 인라인 + 하단 섹션 (이중 표기)
