# 허브 페이지 템플릿 (Hub Template)

> 이 파일은 에이전트가 허브 TSX 파일을 작성할 때 참조하는 **실행 가이드**다.
> 원칙/판단 기준은 → `hub-rules.md` 참조.
> 완성 예시는 → `hub-golden-example.tsx` 참조.

---

## 허브 vs 스포크 — 역할 차이

| 구분 | 허브 (Hub) | 스포크 (Spoke) |
|------|-----------|---------------|
| 역할 | 주제 개관 + 스포크 연결 지도 | 세부 주제 심층 해설 |
| 깊이 | 각 H2를 2~3단락으로 요약 | 각 H2를 5~8단락으로 상세 |
| 핵심 CTA | 스포크 카드 그리드 (spokeGrid) | 허브 복귀 카드 (hubCTA) |
| 내부링크 방향 | → 스포크로 보냄 | ← 허브로 돌려보냄 |
| JSON-LD | BreadcrumbList + FAQPage | BreadcrumbList + FAQPage |
| 시각 컴포넌트 | 가볍게 (표·비교카드 중심) | 풍부하게 (4종+ 필수) |

## 파일 위치·등록

```
src/data/hub/[슬러그].tsx     ← 허브 파일 위치
src/data/hub/registry.ts     ← 여기에 import + 등록
src/data/hub/types.ts        ← HubData 타입 정의
```

### registry.ts 등록 방법

```tsx
import { 개인파산신청자격조건 } from './개인파산-신청-자격-조건'
// ... 기존 import 아래에 추가

export const hubRegistry: Record<string, HubData> = {
  '개인파산-신청-자격-조건': 개인파산신청자격조건,
  // ... 기존 항목 아래에 추가
}
```

## 핵심 구성요소 상세

### 1. spokeGrid — 스포크 카드 그리드 (허브 전용)

허브의 **가장 중요한 역할**: 하위 스포크로 보내는 네비게이션.
hero 바로 아래, 첫 번째 section 전에 위치.

```tsx
spokeGrid: [
  {
    badge: '자격',
    title: '개인파산 신청자격 기준',
    desc: '파산 대상과 신청 요건을 정리했어요.',
    href: '/w/개인파산-신청자격-기준',
  },
  {
    badge: '절차',
    title: '개인파산 신청방법 절차',
    desc: '신청부터 면책까지 단계별 정리.',
    href: '/w/개인파산-신청방법-절차',
  },
  // ... 최소 4개, 최대 12개
],
```

**규칙:**
- badge: 2~3글자로 카테고리 구분 (자격, 절차, 서류, 비용, 비교 등)
- title: 스포크 h1과 동일하거나 축약
- desc: 1줄, ~예요체, 핵심만
- href: `/w/` + 스포크 슬러그
- 순서: 사용자 여정 순 (궁금한 것 → 실행 → 후속)

### 2. sections — H2 본문 (허브 요약 수준)

```tsx
sections: [
  {
    heading: '개인파산 신청은 어떻게 하나요?',
    content: (
      <>
        <p>개인파산 신청은 본인 주소지 관할 지방법원에 하면 돼요. ...</p>
        <p>신청서와 함께 진술서, 채권자목록, 재산목록을 제출해요. ...</p>

        <SpokeTable
          caption="개인파산 신청 필요 서류"
          headers={['서류', '발급처', '비고']}
          rows={[
            ['파산·면책 신청서', '법원 양식', '직접 작성'],
            ['진술서', '법원 양식', '재산·채무 상세 기재'],
            ['채권자목록', '직접 작성', '누락 시 면책 제외'],
          ]}
        />

        <TipBox emoji="💡" title="핵심 포인트">
          채권자목록에서 빠진 채권은 면책 대상에서 제외돼요. 꼼꼼하게 작성하는 게 중요해요.
        </TipBox>
      </>
    ),
  },
  {
    heading: '파산 신청자격은 뭔가요?',
    content: (
      <>
        <p>채무가 재산보다 많고, 갚을 능력이 없으면 신청할 수 있어요. ...</p>
        <p>소득이 있어도 채무를 감당할 수 없으면 해당돼요. ...</p>
      </>
    ),
  },
  // H2 3~4개 (spoke와 달리 4개 이하로 간결하게)
  {
    heading: null,  // → FAQ 자동 삽입 위치
    content: null,
  },
],
```

**허브 sections 규칙:**
- H2 개수: 3~4개 (스포크보다 적음)
- 단락 수: H2당 2~3단락 (스포크의 5~8단락보다 짧음)
- 깊이: 개요 수준으로만. "자세한 내용은 스포크에서" 유도
- 시각 컴포넌트: H2당 0~1개 (테이블·비교카드 중심)
- 마지막에 `{ heading: null, content: null }` → FAQ 자동 삽입

### 3. H2 말미 스포크 유도 (spokeLink)

각 H2의 마지막 단락에서 관련 스포크로 유도:

```tsx
<p>
  자격 요건을 더 자세히 알고 싶다면{' '}
  <a href="/w/개인파산-신청자격-기준" className="text-emerald-600 font-semibold hover:underline">
    개인파산 신청자격 기준
  </a>
  에서 확인해보세요.
</p>
```

**규칙:**
- 매 H2 끝에 1~2개 스포크 링크 필수
- 자연스러운 문장 안에 삽입 (단독 "관련 글 보기" 금지)
- className은 `text-emerald-600 font-semibold hover:underline`

### 4. faq — 자주 묻는 질문

```tsx
faq: [
  {
    question: '개인파산 신청하면 불이익이 있나요?',
    answer: '파산 선고 중에는 일부 자격이 제한돼요. 하지만 면책 후 복권되면 모든 제한이 풀려요. 신용정보는 면책 확정 후 5년간 등록돼요.',
  },
  // 최소 3개, 최대 5개
],
```

**규칙:**
- 3~5개 (스포크의 2~4개보다 약간 많음)
- 허브 전체를 아우르는 넓은 질문
- ~예요체 필수 (예외 없음)
- answer는 2~3문장 (스포크 FAQ보다 약간 김)

### 5. sources — 출처

```tsx
sources: [
  { label: '대한민국 법원 — 개인파산·면책', url: 'https://www.scourt.go.kr/...' },
  { label: '법률구조공단 — 파산 안내', url: 'https://www.klac.or.kr/...' },
  // 최소 2개
],
```

## 사용 가능한 시각 컴포넌트

허브에서는 **가벼운 컴포넌트** 위주로 사용. 스포크처럼 4종+ 강제하지 않음.

| 컴포넌트 | 허브 적합도 | 용도 |
|----------|-----------|------|
| `SpokeTable` | ⭐⭐⭐ | 비교표, 요약표 — 허브의 주력 |
| `SpokeCompareCards` | ⭐⭐⭐ | A vs B 비교 (파산 vs 회생 등) |
| `SpokeTimeline` | ⭐⭐ | 절차 타임라인 요약 |
| `SpokeStepCards` | ⭐⭐ | 단계별 안내 요약 |
| `TipBox` | ⭐⭐ | 핵심 포인트 1~2개 |
| `SpokeFlow` | ⭐ | 흐름도 (복잡하면 스포크로) |
| `FormulaBox` | ⭐ | 계산식 (허브에선 드물게) |
| `SpokeRateBars` | ⭐ | 수치 비교 (허브에선 드물게) |
| `SpokeWarnBox` | ⭐ | 경고 (허브에선 드물게) |
| `SpokeChecklist` | ❌ | 허브에 부적합 — 스포크 전용 |
| `RateCards` | ❌ | 허브에 부적합 — 스포크 전용 |
| `BridgeCTA` | ❌ | 허브에서 사용 금지 — 스포크 전용 |

**허브 시각 규칙:**
- 전체 페이지에서 시각 컴포넌트 2~4개 (스포크의 4종+보다 적음)
- SpokeTable이 가장 자주 쓰임
- 연속으로 같은 컴포넌트 2번 금지 (스포크와 동일)

## 서론 작성 공식 (허브용)

```
[1줄] 주제 정의 + 핵심 정보 (숫자 포함)
[1줄] 이 글에서 다루는 범위 요약
```

**✅ 좋은 예:**
```
개인파산은 빚을 갚을 수 없는 상태에서 법원에 신청하는 제도예요.
면책까지 받으면 남은 채무를 전부 탕감받아요.

신청 자격, 절차, 필요 서류, 관할법원까지
— 이 글에서 전체 흐름을 정리했어요.
```

**❌ 나쁜 예 (절대 금지):**
```
❌ "개인파산에 대해 알아보겠습니다" (문어체 + 주어 없음)
❌ "이번 포스팅에서는 ~를 살펴보겠습니다" (블로그체)
❌ "많은 분들이 궁금해하시는 ~" (네이버 블로그체)
❌ "개인파산이란 무엇일까요?" (의문형 서두)
❌ "오늘은 개인파산에 대해서 정리해보려고 합니다" (일기체)
```

## 전환 스타일 (섹션 연결)

허브에서는 H2 간 전환이 **간결**해야 해요. 스포크처럼 5종 변형을 쓰지 않고, 2~3종만 사용.

**허브 전환 패턴:**

```
A. 주제 전환형
"신청 자격을 확인했으니, 이제 실제 절차를 볼게요."

B. 요약-연결형  
"비용은 인지대 + 예납금으로 구성돼요. 절감 방법도 있어요."
```

**금지 표현:**
```
❌ "그럼 이번에는 ~에 대해 알아볼까요?" (의문형)
❌ "다음으로 ~를 살펴보겠습니다" (문어체)
❌ "자, 이제 ~로 넘어가 볼게요" (구어체 과잉)
```

## 허브 전용 금지 사항

| # | 금지 | 이유 |
|---|------|------|
| 1 | `BridgeCTA` 사용 | 허브 자체가 허브. 자기 자신으로 보내면 안 됨 |
| 2 | 스포크 내용 복사 | 허브는 요약만. 스포크와 동일 문장 금지 |
| 3 | H2 5개 이상 | 허브는 간결. 4개 이하 필수 |
| 4 | 시각 컴포넌트 5개 이상 | 허브는 가볍게. 스포크와 차별화 |
| 5 | spokeGrid 없이 발행 | 스포크 연결이 허브의 존재 이유 |
| 6 | ~습니다/~됩니다 문어체 | 스포크와 동일. ~예요체 필수 |
| 7 | 스포크 심층 내용 포함 | "자세한 내용은 [스포크]에서" 유도 |
| 8 | relatedSpokes 사용 | 허브에는 spokeGrid가 있으므로 불필요 |
