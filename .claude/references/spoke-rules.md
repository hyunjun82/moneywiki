# 스포크 글 작성 규칙서

> **골든 예시**(`spoke-golden-example.tsx`)를 먼저 읽고, 이 규칙서를 읽어라.
> 예시 = "이렇게 써라", 규칙서 = "왜 이렇게 쓰는지 + 새 주제에 적용하는 법"

---

## 1. 도입부 공식 (hero.intro)

**3줄 필수 + 4줄째 선택. 같은 허브 내 스포크끼리 같은 유형 금지.**

### 5가지 도입부 유형 (순환 필수!)

**유형 A: 상황 공감형** (가장 기본)
```
1줄: 독자의 구체적 상황 묘사
2줄: 이 글로 해결된다는 약속
3줄: 구체 숫자/범위
```
```
퇴직했는데 회사가 퇴직금을 한참 뒤에 줬어요. 억울하잖아요.
14일 넘기면 연 20% 이자를 추가로 받을 수 있어요.
계산법부터 청구 절차까지 알려드릴게요.
```

**유형 B: 숫자 충격형** (금액/비율이 핵심인 글)
```
1줄: 놀라운 숫자로 시작
2줄: 왜 그런지 맥락
3줄: 독자 행동 유도
```
```
퇴직금 1,000만 원을 30일 늦게 받으면 약 16만 원 더 받아요.
연 20%라는 지연이자가 자동으로 붙거든요.
내 경우엔 얼마인지 아래에서 바로 계산해 보세요.
```

**유형 C: 오해 교정형** (잘못 알려진 정보)
```
1줄: 많이들 잘못 알고 있는 사실
2줄: 실제로는 이렇다
3줄: 구체 기준/조건
```
```
"자진퇴사하면 실업급여 못 받는다"고 알고 계시죠? 꼭 그렇진 않아요.
임금체불이나 직장 내 괴롭힘 때문에 그만뒀다면 받을 수 있어요.
정당한 이직 사유 7가지를 정리했어요.
```

**유형 D: 비교 선택형** (A vs B 주제)
```
1줄: 두 선택지 제시
2줄: 핵심 차이점 한 줄
3줄: 독자 상황별 결론
```
```
전세 vs 월세, 지금은 뭐가 유리할까요?
금리 3.5% 기준으로 전세가 2억이면 월세 환산 58만 원이에요.
보증금 여력에 따라 답이 달라지는데, 아래에서 비교해 보세요.
```

**유형 E: 스토리형** (절차/경험 중심)
```
1줄: 실제 상황 스토리
2줄: 핵심 결과/교훈
3줄: 독자에게 적용
```
```
지인이 국민연금 추납을 1년 미루다가 월 12만 원을 더 냈어요.
추납 보험료는 매년 오르거든요. 빨리 할수록 이득이에요.
신청 조건부터 납부 금액까지 순서대로 정리했어요.
```

### 유형 배분 규칙
```
같은 허브 내 스포크 8개 기준:
  스포크 1: A형  스포크 2: B형  스포크 3: C형  스포크 4: D형
  스포크 5: E형  스포크 6: A형  스포크 7: B형  스포크 8: C형

같은 유형 연속 2번 금지. 형제 스포크와 1줄째가 같은 감정이면 FAIL.
```

### 4줄째 (선택): 동행 톤으로 첫 섹션 안내
- "먼저 월급별 세금표부터 볼게요."
- "차례대로 확인해볼게요."
- 같은 허브 아래 스포크끼리 4줄째 패턴 겹치면 FAIL

### 절대 금지
- "~하고 계신가요?" (네이버 블로그체)
- "이 글 하나로 정리했어요" (AI 상투어)
- "~시달리고 있다면" (과장)
- "오늘은 ~에 대해" (일기체)
- "많은 분들이" (블로그체)

## 2. 문체 규칙

### 필수
- **~예요체** (~이에요, ~해요, ~돼요)
- **문장 30자 이내** 권장 (한 문장이 길어지면 끊어라)
- **독자 감정 먼저** → 정보는 그다음
- **정보 나열 금지** — "A하고 B하고 C해요" 대신 맥락을 줘라

### 톤 통일 범위 (예외 없음!)
- hero.intro, 본문 텍스트, bridgeCTA, **FAQ 답변** 모두 동일한 ~예요체
- FAQ answer에서 "~됩니다", "~합니다" 쓰면 FAIL
- 출처 인용문만 예외 (법령 원문 등)

### 금지
- ~습니다 (경어체)
- "~알아보겠습니다", "~살펴보겠습니다"
- 같은 문장 구조 3회 이상 반복 ("X하면 Y해요" 패턴 반복)
- 같은 문장 시작어 3회 이상 반복 ("참고로~", "특히~")
- 같은 형용사/부사 3회 이상 반복 ("정확히", "꼼꼼히")

### 좋은 예 vs 나쁜 예
```
❌ "간이세액표는 국세청이 발표하는 표입니다. 이 표는 매년 고시됩니다."
✅ "국세청이 매년 발표하는 기준표예요. 회사는 이 표대로 원천징수해요."

❌ "80%를 선택하면 적게 떼입니다. 100%를 선택하면 기본입니다. 120%를 선택하면 많이 떼입니다."
✅ "어떤 비율을 골라도 연간 세금 총액은 같아요. 차이는 매달 미리 내는 금액뿐이에요."
```

## 3. 섹션 전환 규칙

**모든 섹션 끝에 전환 문장 필수. 4개 섹션의 전환이 같은 패턴이면 FAIL.**

### 5가지 전환 스타일 (3가지 이상 섞기)

| 스타일 | 패턴 | 예시 |
|--------|------|------|
| A. 독자 대변형 | "~싶잖아요" | "표에서 대략은 알겠는데 내 월급에선 정확히 얼마인지 계산해 보고 싶잖아요." |
| B. 자연 호기심형 | "~궁금한 게 생기죠" | "여기까지 보면 한 가지 궁금한 게 생기죠." |
| C. 간결 연결형 | "~넘어갈게요" | "금액을 알았으니 자격 요건으로 넘어갈게요." |
| D. 화제 전환형 | "~주의할 게 있어요" | "그런데 한 가지 주의할 게 있어요." |
| E. 실용 연결형 | "~정리했어요" | "비율까지 정했으면 진짜 실수령액을 정리했어요." |

### 절대 금지
- "그렇다면 X는 Y일까요?" → 글 전체 최대 1회
- "~ 볼 차례예요" → 기계적 순서
- "다음으로 ~ 알아볼게요" → 빈 전환
- 전환 문장은 **그 주제의 구체적 내용**을 담아야 한다

## 4. bridgeCTA 규칙

각 섹션 하단에 **다음 섹션의 "독자가 자연스럽게 궁금해할 질문"**으로 구성.

```tsx
bridgeCTA: {
  href: '#s2',           // 다음 섹션 ID (마지막은 허브/계산기 URL)
  badge: '간편 계산',     // 2~4글자 키워드
  title: '내 월급에서 세금이 얼마나 빠질까?',  // 궁금증 유발 질문
  desc: '내 월급으로 직접 계산해보기',          // 행동 유도 한 줄
  icon: 'calc',          // calc | clock | info | grid | check
  primary: false,        // 마지막 섹션만 true (허브/계산기 연결)
}
```

- 마지막 본문 섹션의 bridgeCTA → `primary: true` + 허브/계산기 연결
- 기계적 질문 반복 금지 ("~알고 싶다면?" 4번 반복 = FAIL)

## 5. 컴포넌트 선택 기준

> **핵심**: "이 내용을 독자가 가장 빨리 이해하려면 어떤 형태가 좋을까?"

| 내용 성격 | 추천 컴포넌트 | 이유 |
|-----------|-------------|------|
| 숫자/세율 비교 | `SpokeTable` | 나란히 비교가 편해서 |
| 계산식/공식 | `FormulaBox` | 코드처럼 한눈에 |
| 2~3가지 선택지 | `RateCards` | 카드형이 직관적 |
| 꼭 기억할 한 가지 | `TipBox` | 시선을 확실히 잡으니까 |
| 기한/일정 순서 | `SpokeTimeline` | 시간 흐름이 한눈에 |
| 단계별 절차 | `SpokeStepCards` | 따라하기 쉬워서 |
| A vs B 비교 | `SpokeCompareCards` | 나란히 비교 |
| 비율/퍼센트 | `SpokeRateBars` | 막대로 직관적 비교 |
| 프로세스 흐름 | `SpokeFlow` | 전체 과정 한눈에 |
| 주의/경고 | `SpokeWarnBox` | 놓치면 안 되는 내용 |
| 서류/조건 체크 | `SpokeChecklist` | 빠진 거 없나 확인 |

### 인터랙티브 컴포넌트 (미구현 — 정적 대체 필수)

아래 컴포넌트는 골든 예시 HTML에만 존재하며, 현재 TSX로 구현되지 않았다.
**사용하고 싶으면 가장 가까운 정적 컴포넌트로 대체**해야 한다.

| 인터랙티브 원본 | 정적 대체 | 대체 이유 |
|----------------|-----------|-----------|
| 세금 계산기 (SpokeTaxCalculator) | `FormulaBox` + `SpokeTable` | 계산식 노출 + 구간별 결과표 |
| 비교 슬라이더 (SpokeComparisonSlider) | `SpokeCompareCards` 또는 `SpokeRateBars` | 나란히 비교 또는 비율 시각화 |
| 진단 마법사 (SpokeWizard) | `SpokeFlow` + `RateCards` | 분기 흐름도 + 결과 카드 |

> 인터랙티브 컴포넌트가 TSX로 구현되면 이 표를 위 메인 테이블로 이동시킬 것.

### 필수 규칙
- 섹션당 시각 요소 **최소 1개**
- 글 전체에서 **4종류 이상** 사용
- 텍스트(4문장+) 먼저 → 시각 요소 뒤에
- SpokeTable은 글 전체 **2개 이하**
- 같은 컴포넌트 **연속 사용 금지** (Table → Table 안 됨)
- TipBox는 전체 시각요소의 **40% 이하**
- **형제 스포크와 시각 조합 겹치면 FAIL**

### 형제 스포크 중복 확인 방법

같은 허브 아래 스포크를 작성할 때, 기존 형제 스포크와 **3가지를 비교**해야 한다:

```
1. 시각 조합 비교
   - 기존 스포크 TSX 파일을 열어 사용된 컴포넌트 종류 확인
   - 예: 형제A = [SpokeTable, TipBox, FormulaBox, RateCards]
   - 새 글은 최소 2종류 이상 다르게 구성
   - 확인법: Glob("src/data/spoke/[허브슬러그]*.tsx") → 각 파일의 import 문 확인

2. 서론(hero.intro) 비교
   - 형제 스포크의 1줄째(독자 상황)와 4줄째(동행 톤)가 겹치면 FAIL
   - 같은 감정 키워드 사용 금지 (예: 두 글 모두 "막막하다면")

3. 전환 문장 비교
   - 형제 스포크가 사용한 전환 스타일(A~E) 확인
   - 같은 순서로 같은 스타일 사용 금지
```

리더(spoke-writer.md)가 `sibling_visuals` 필드로 형제 정보를 제공하면 그것을 우선 참고한다.
제공되지 않으면 위 방법으로 직접 확인한다.

## 6. Quick Answer (hero 영역)

Quick Answer와 hubCTA는 **별개 요소**다.

### Quick Answer (Featured Snippet 타깃)
- hero 영역 바로 아래, 본문 시작 전 위치
- Google Featured Snippet(0번 위치) 노출을 목표로 함
- H2-1의 핵심 답변을 **2~3문장**으로 압축
- 구어체 유지, 구체적 숫자 포함
- 현재 SpokeData 타입에 quickAnswer 필드 없음 → hero.intro 하단 또는 별도 주석으로 표기

```tsx
// Quick Answer 예시 (Featured Snippet 타깃)
// "간이세액표는 국세청이 매년 고시하는 월급별 소득세 기준표예요.
//  월급 300만원 기준 소득세는 약 6만원이고, 부양가족 수에 따라 달라져요."
```

### hubCTA (허브 연결 카드)
- Quick Answer 아래에 위치하는 허브 페이지 연결 카드
- hubCTA.badge: 2글자 키워드 ("올인원", "핵심", "한눈에")
- hubCTA.desc: 허브 페이지의 핵심 가치를 **한 줄**로 요약
- 계산기/도구 페이지로 자연스럽게 유도

## 7. FAQ 규칙

- **2개 고정** (frontmatter/data 전용, 본문에 FAQ 섹션 금지)
- H2와 **겹치지 않는** 실무 질문만
- 베이스 키워드 포함
- `<strong>` 태그로 핵심 강조
- 구어체 답변

## 8. CTA/링크 규칙

| 위치 | 규칙 |
|------|------|
| 모든 섹션 하단 | bridgeCTA (다음 섹션 또는 내부 페이지) |
| 마지막 섹션 | primary CTA → 허브/계산기 |
| 본문 인라인 (출처) | 출처 링크 (정부/공식 사이트) |
| 본문 인라인 (내부) | 형제 스포크/허브 키워드 링크 (나무위키 방식) |
| relatedSpokes | 같은 허브 내 형제 스포크 2~4개 |

- 내부링크: `/w/슬러그` (새창 안 열림)
- 외부링크: `target="_blank" rel="noopener noreferrer"`
- **존재하지 않는 슬러그 연결 금지**

### 본문 인라인 내부링크 (나무위키 방식)

본문에서 형제 스포크/허브의 핵심 키워드가 자연스럽게 언급될 때, `<a href="/w/슬러그">키워드</a>`로 연결한다.

```
규칙:
1. 스포크당 최소 2개, 최대 5개
2. 같은 슬러그 반복 링크 금지 — 첫 등장에만 링크
3. 출처 링크(정부/공식 사이트)와 별도 — 둘 다 넣어야 함
4. 자연스러운 문맥에서만 — 억지로 키워드를 끼워넣지 않음
5. 같은 허브 내 형제 스포크 + 부모 허브만 대상
6. 실존 슬러그만 (Glob 확인 필수)
```

예시:
```tsx
// 비과세 스포크 → 유형 스포크로 연결
<a href="/w/ISA계좌-중개형-서민형-일반형-유형-선택-기준">서민형</a>은 400만원까지 세금이 0원이에요

// 가입 스포크 → 납입 스포크로 연결
<a href="/w/ISA계좌-납입한도-연간-2000만원-이월-규정">연간 한도 2,000만원</a>을 꽉 채우려면
```

### relatedSpokes 선택 기준

```
1. 같은 허브 내 형제 스포크 중 2~4개 선택
2. 선택 우선순위:
   - 이 글을 읽은 독자가 자연스럽게 궁금해할 주제
   - 이 글에서 언급했지만 자세히 다루지 않은 주제
   - 이 글의 결론에서 "다음 단계"에 해당하는 주제
3. 금지:
   - 실제 존재하지 않는 스포크 TSX 파일 연결
   - 같은 허브가 아닌 다른 허브의 스포크 연결
   - 내용적 연관성 없는 스포크 (개수 채우기 금지)
4. 확인법: Glob("src/data/spoke/*.tsx") 로 실제 존재하는 파일만 연결
```

## 10. 데이터 정확성 규칙

> 숫자 하나 틀리면 글 전체 신뢰도가 무너진다.

### 필수 검증
- 본문에 사용한 **모든 수치**는 출처와 대조해야 한다
- 출처에서 직접 확인할 수 없는 숫자는 **절대 사용 금지** (임의 생성 = FAIL)
- 근사치는 반드시 "약", "대략", "~정도" 표기 (예: "약 6만원")
- 연도 표기 필수: "2026년 기준" 등 시점 명시

### 핵심 수치 크로스체크
```
□ 세율/공제율 → 국세청(nts.go.kr) 또는 국세법령정보(taxlaw.nts.go.kr)
□ 지원금 금액 → 해당 부처 공식 사이트 (moel.go.kr, bokjiro.go.kr 등)
□ 기한/일정 → 법령 원문 (law.go.kr)
□ 이자율/수수료 → 금융감독원(fss.or.kr) 또는 해당 금융기관
```

### 금지
- 출처 없는 숫자 생성 (예: "보통 50만원 정도" ← 근거 없으면 FAIL)
- 다른 연도 기준 숫자를 현재 연도로 표기
- 블로그/개인 사이트 숫자 인용

## 11. 절대 금지

- 이모지
- ~습니다 (경어체)
- 테이블 3개 이상
- H2에 숫자 (`## 1. 제목` ❌)
- 콜론(:) 타이틀
- 시각 요소 없는 텍스트만 섹션

- 같은 허브 내 스포크끼리 서론/시각 조합/전환 문장 겹침
- 시키지 않은 파일 수정
- 티스토리/네이버블로그/브런치/개인블로그/위키백과 검색/참고/인용
