# 허브 페이지 규칙서 (Hub Rules)

> 이 파일은 "왜" + 판단 기준만 다룬다.
> "어떻게" + 코드 예시는 → `hub-template.md` 참조.
> 참고용 골든 예시: `src/data/hub/기초생활수급자-조건-총정리.tsx` (구조만 참고, 복사 금지)

---

## 핵심 원칙 — 허브의 존재 이유

허브는 **지도(Map)**다. 목적지(스포크)로 가는 길을 알려주는 역할.
독자가 "어떤 스포크를 읽어야 할지" 30초 안에 판단할 수 있어야 한다.

---

## 규칙 10개

### 1. 구어체 필수 (~이에요, ~해요, ~돼요)

적용 범위: hero, sections, faq, tipbox, warnbox 등 페이지 내 모든 텍스트.
FAQ answer도 예외 없음. ~습니다/~됩니다 사용 금지.

### 2. 허브는 요약만 — 심층은 스포크에서

각 H2는 2~3단락으로 핵심만 요약.
스포크에서 다루는 세부 정보(계산법, 양식 작성법, 판례 등)를 허브에 넣지 않는다.
매 H2 끝에 관련 스포크 링크로 유도.

### 3. Checker가 1번 섹션 + spokeGroups가 하단

Checker = 독자 진입 시 바로 노출. sections 1번에 배치.
독자가 버튼을 눌러보면서 체류시간 증가.
spokeGroups = 하단에 전체 스포크 목록. 모든 하위 스포크를 빠짐없이 포함.
sectionSpoke = 각 섹션 끝에 관련 스포크 내부링크 카드 (목차가 아님!).
chips = hero 아래 4칸 네비게이션, 반드시 스포크 내부링크(/w/).

### 4. H2는 4~5개 (PAA 기반, 베이스키워드 필수)

허브 H2 = 해당 주제의 핵심 질문 4~5개.
모든 H2에 베이스 키워드 포함 필수.
H2 텍스트는 질문형(?) 필수.

### 5. 시각 컴포넌트는 가볍게 (2~4개)

허브는 텍스트 중심. 시각은 보조.
SpokeTable이 주력. 비교 주제면 SpokeCompareCards.
BridgeCTA는 허브에서 절대 사용 금지.

### 6. quickAnswer = Featured Snippet 타겟

hero에 quickAnswer 필수.
H2-1의 핵심 답변 3줄 이내 + 구체 숫자 1개 이상.
hook은 spokeGrid 또는 본문으로 유도하는 한 줄.

### 7. 출처 정부/공식 사이트 우선 (WebFetch 우선)

- 1순위: 정부·공공기관 (법원, 국세청, 고용노동부 등)
- 2순위: 대형 금융사이트 자체 도메인 (toss.im, kbfg.com 등)
- 금지: 블로그(네이버/티스토리/위키백과), 개인사이트
- 숫자 데이터는 sources 출처 기준으로만 작성
- 에이전트가 임의로 숫자를 생성하거나 계산 금지
- 연도 표기 필수 (2026년 기준)

### 8. 스포크와 내용 중복 금지

같은 문장을 허브와 스포크에 동시에 쓰면 카니발라이제이션 발생.
허브는 "무엇인가" + "왜 중요한가" 수준.
스포크는 "어떻게 하는가" + "구체적으로 얼마인가" 수준.

비교 예시:
```
허브: "개인파산 신청비용은 인지대와 예납금으로 구성돼요."
스포크: "인지대는 3만 원이에요. 예납금은 채권자 수에 따라 달라지는데, 
       채권자 10명 기준으로 약 50만~80만 원 수준이에요."
```

### 9. 내부링크 방향 — 허브 → 스포크

허브에서 다른 허브로 링크하지 않는다 (같은 토픽 내에서).
허브 → 스포크로만 보낸다.
다른 토픽의 허브 링크는 relatedHubs에서만 (선택 사항).

### 9-1. sectionSpoke + chips = 내부링크 (스포크 URL)

sectionSpoke와 chips의 href는 **반드시 스포크 내부링크(/w/슬러그)**여야 한다.
앵커(#)로 같은 페이지 내 이동이 아니라, 다른 스포크 글로 이동하는 네비게이션.

```
규칙:
1. sectionSpoke: 각 섹션 끝에 관련 스포크 1~4개 배치
2. chips: hero 아래 4칸, 각각 다른 스포크로 이동
3. href는 /w/슬러그 형태만 (# 앵커 금지)
4. 실존 슬러그만 (Glob 확인 필수)
5. 허브 → 자기 스포크만 대상 (다른 허브의 스포크 금지)
```

### 9-2. 본문 인라인 내부링크 (나무위키 방식)

허브 본문에서 스포크 키워드가 자연스럽게 언급될 때, `<a href="/w/슬러그">키워드</a>`로 연결한다.

```
규칙:
1. 허브당 최소 2개, 최대 5개
2. 같은 슬러그 반복 링크 금지 — 첫 등장에만 링크
3. 출처 링크(정부/공식 사이트)와 별도 — 둘 다 넣어야 함
4. 자연스러운 문맥에서만 — 억지로 키워드를 끼워넣지 않음
5. 실존 슬러그만 (Glob 확인 필수)
```

### 10. 절대 금지

| # | 금지 | 탐지 패턴 |
|---|------|----------|
| 1 | ~습니다/~됩니다 | 문어체 종결어미 |
| 2 | "알아보겠습니다" | 블로그 서두 |
| 3 | "많은 분들이" | 네이버 블로그체 |
| 4 | "이번 포스팅" | 블로그 지시어 |
| 5 | "살펴보겠습니다" | 문어체 전환 |
| 6 | "~란 무엇일까요?" | 의문형 서두 |
| 7 | "오늘은 ~해보려고" | 일기체 서두 |
| 8 | BridgeCTA 컴포넌트 | 허브에서 불필요 |
| 9 | 스포크 본문 복사 | 동일 문장 금지 |
| 10 | 5줄 이상 단락 | 허브는 간결하게 |

## 품질 자가 검증 체크리스트

에이전트는 허브 작성 완료 후 아래 항목을 반드시 확인:

```
□ Checker가 sections 1번인가?
□ spokeGroups에 하위 스포크 전부 포함됐나?
□ chips 4개의 href가 스포크 내부링크(/w/)인가?
□ sectionSpoke의 href가 스포크 내부링크(/w/)인가?
□ heroCTA가 #checker로 연결되는가?
□ prevNext 있음?
□ H2가 4~5개이고 질문형(?)인가?
□ 모든 H2에 베이스 키워드 포함?
□ 시각 컴포넌트가 2~4개인가?
□ 모든 텍스트가 ~예요체인가? (FAQ answer 포함)
□ 스포크와 동일한 문장이 없나?
□ sources에 정부/공식 사이트 2개 이상인가?
□ meta.title에 | 구분자?
□ meta.description 100~150자, 구어체 2문장?
□ meta.keywords가 4개인가?
□ spokeGroups title에 이모지 없음?
□ registry.ts 등록?
```
