# 머니위키 글 작성 에이전트

> **"20~80대 누구나 이해 + 궁금증 100% 해결 + 이 글 하나로 끝"**

핵심 원칙:
- 구어체 (~이에요, ~해요, ~하죠)
- 전문용어 → 쉬운 말
- 결론 먼저, 섹션당 4문장 이상

**검증은 훅(verify-wiki-quality.js)이 Write 시 자동 실행. 이 파일은 워크플로우 + 금지규칙 담당.**

## Step 1: 타이틀-키워드-H2 생성

keywords.md 규칙대로 생성. (훅이 콜론/32자/키워드4개/H2질문형 자동 검증)

### H2 자연스러움 (필수!)

H2 = 친구한테 질문하듯 자연스러운 대화체. "키워드 + 질문접미사" 기계적 붙이기 금지.

```
❌ 기계적 (키워드 그대로 + 접미사):
  "두루누리 지원 대상은 누구인가요?"
  "두루누리 신청 방법은 어떻게 되나요?" (방법+어떻게 = 중복)
  "퇴직금 지급 기준은 무엇인가요?"

✅ 대화체 (사람이 실제로 궁금해하는 질문):
  "두루누리 지원 대상은 어떻게 되나요?"
  "두루누리 신청은 어떻게 하나요?"
  "퇴직금 지급 기준은 뭔가요?"

판단법: "이 질문을 실제로 검색창에 칠까?" → Yes면 OK
```

## Step 2: 정보 수집

### WebFetch 우선 (정부/공식 출처)

```
정책/제도: https://www.gov.kr
금융: https://www.fsc.go.kr
세금: https://www.nts.go.kr
법령: https://www.law.go.kr
근로: https://www.moel.go.kr
복지: https://www.bokjiro.go.kr
연금: https://www.nps.or.kr
개인정보: https://www.privacy.go.kr
```

1. 키워드 → 해당 정부기관 파악
2. WebFetch(공식URL, "[키워드] 2026 최신 정보")
3. 성공 → Step 3 / 실패 → WebSearch fallback

### WebSearch (fallback만)

```
"[키워드] 2026 공식"
"[키워드] site:gov.kr"
"[키워드] 조건 자격 방법"
```

## Step 3: 기존 위키 스캔 (내부링크 + relatedDocs)

```bash
ls content/wiki/ | grep -i "[관련단어]"
```

### 내부링크 관련성 규칙 (필수!)

**같은 제도, 같은 대상, 같은 절차**에 해당하는 글만 링크.

```
❌ 관련 없는 링크 (개수 채우기용):
  두루누리 글에서 → [실업급여 계산기], [연봉 실수령액 계산기]
  전세보증금 글에서 → [퇴직금 계산기]

✅ 관련 있는 링크:
  두루누리 글에서 → [4대보험], [국민연금 가입], [고용보험 가입]
  전세보증금 글에서 → [전입신고 방법], [임대차보호법], [전세보증보험]
```

- 관련 글이 3개 미만이면 2개도 OK. 억지 링크보다 없는 게 낫다.
- 계산기 링크는 해당 계산과 직접 관련될 때만 (4대보험료 계산기 → 두루누리 OK)

### relatedDocs 관련성 규칙

frontmatter relatedDocs도 동일 기준. **같은 주제/제도의 글만.**

```
❌ 두루누리 글에 relatedDocs: 실업급여 계산기, 연봉 계산기
✅ 두루누리 글에 relatedDocs: 4대보험 가입 방법, 국민연금 가입 조건
```

관련 글이 없으면 relatedDocs 비워두기.

## Step 4: 본문 작성

### 서론 4줄 패턴 (template3358 필수!)

주제 유형 먼저 판단:

| 유형 | 판단 기준 | 서론 2줄 패턴 | 서론 4줄 패턴 |
|------|----------|-------------|-------------|
| **행동형** (신청/계산/조회) | 독자가 뭔가 해야 함 | 구체적 숫자 + **"아시나요"** | 3줄 "정리해드릴게요" + 4줄 "미리 ~하시는 분들 많더라고요" |
| **정보형** (개념/비교/차이) | 독자가 알고 싶음 | 모르면 손해 + **"아시나요"** | 3줄 "정리해드릴게요" + 4줄 "요즘 ~분들 많더라고요" |

```
❌ 2줄 "~수 있어요" (아시나요 빠짐):
  "10명 미만 사업장이라면 보험료 80%를 지원받을 수 있어요."

✅ 2줄 행동형 (아시나요 + 긴급감):
  "10명 미만 사업장이면 보험료 80%를 3년이나 지원받을 수 있다는 거 아시나요."

❌ 4줄 정보형 (행동 키워드인데):
  "요즘 두루누리 지원 대상 확인하시는 분들 많더라고요."

✅ 4줄 행동형 (신청 촉구):
  "지원 기간이 정해져 있어서 미리 신청하시는 분들 많더라고요."
```

### 키워드 배치 규칙 (가장 중요! 템플릿 패턴 필수!)

**full keyword(예: "두루누리 지원 대상")는 H2 제목에만 사용. 본문에서는 절대 full keyword 그대로 쓰지 말고 자연어로 쪼개서 배치.**

템플릿 예시 분석:
```
keywords: ["퇴직금 지연이자", "퇴직금 지연이자 청구", "퇴직금 이자율 계산", "퇴직금 청구 방법"]

## 퇴직금 지연이자는 얼마나 되나요?  ← H2에 full keyword
  본문: "퇴직금 지급이 14일을 넘으면..." ← "퇴직금" + "지급" 자연어
  본문: "이 기한을 넘기면 지연이자가..." ← "지연이자" 단독
  본문: "퇴직금 1,000만원을 30일..." ← "퇴직금" 단독
  → "퇴직금 지연이자" full phrase = 본문 0회!

## 퇴직금 지연이자 청구는 어떻게 하나요?  ← H2에 full keyword
  본문: "지연이자는 형사처벌 대상이..." ← "지연이자" 단독
  본문: "퇴직금은 노동청 진정으로..." ← "퇴직금" 단독
  → "퇴직금 지연이자 청구" full phrase = 본문 0회!
```

규칙:
- H2 제목 = full keyword + 질문형
- 본문 = 키워드를 구성 단어로 쪼개서 자연스럽게
- full keyword 통째로 본문에 쓰면 훅이 삭제함
- "이 제도", "지원 자격", "해당 조건" 등으로 바꿔쓰기

### 억지 비유/연결 금지

내부링크를 넣으려고 관련 없는 비유 만들지 말 것.

```
❌ "실업급여 계산기처럼 전체 36개월 중에서..." (실업급여와 두루누리는 관련 없음)
❌ "연봉 실수령액 계산기에서 4대보험료가 얼마나 빠지는지..." (맥락 안 맞음)
✅ 관련 링크만 자연스럽게: "[4대보험료 계산기](/w/4대보험료-계산기)에서 내 보험료를 확인해보세요."
```

### 시각 요소 규칙

| 이런 상황이면 | 이 시각 요소 필수 | 예시 |
|-------------|----------------|------|
| A vs B 분기 (신규/기존, 정규직/계약직) | **선택 분기 불릿** | **신규 가입자라면** → 자동 신청 / **기존 가입자라면** → 별도 신청 |
| 핵심 숫자 한줄 강조 | `> blockquote` (2문장 이내!) | > 월 보수 270만원 미만 + 10명 미만 사업장 = 지원 대상 |
| 금액/조건 비교 | 테이블 (최대 2개) | 지원 전/후 보험료 비교표 |
| 3개 이상 서류/단계 | 번호 리스트 또는 서류 테이블 | 신청 절차 1→2→3→4 |

```
❌ blockquote에 2개 다른 정보 섞기:
  > 재산 6억 이상이면 제외돼요. 신규 가입자는 자동 신청이에요.

✅ blockquote = 핵심 한줄만:
  > 월 보수 270만원 미만 + 10명 미만 사업장 = 지원 대상

✅ 분기는 선택 분기 불릿으로:
  **신규 가입자라면** → 자동으로 신청돼요, 별도 절차 없음
  **기존 가입자라면** → [4대보험센터](https://www.4insure.or.kr)에서 직접 신청해야 해요
```

텍스트로 먼저 설명 → 시각 요소로 보강 (테이블이 본문 대체하면 안 됨)
