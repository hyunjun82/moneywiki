# 허브 & 스포크 키워드 → 타이틀 → H2 생성기

## 사용법
사용자가 PAA 질문/키워드 입력 → 허브/스포크 구분 → title/keywords/H2 생성

---

## 공통 규칙

```
금지어 (타이틀/키워드 모두):
  ❌ 총정리, 완벽정리, 정리, 가이드, 가이드북
  ❌ 확인, 비교표, 서류
  ❌ 부자연스러운 조합
  ❌ 아무도 검색 안 하는 억지 키워드

타이틀 공통 패턴:
  [메인 롱테일] — [추가 롱테일 자연 배치]
  모든 추출 키워드 = 실제 검색어 (볼륨 낮아도 OK)
  — 뒤쪽도 구체적 행동 표현! (억지 나열 금지)

  ❌ "부동산 가압류 신청 방법 — 관할법원 확인"
  ✅ "부동산 가압류 신청 방법 — 관할법원 선택과 비용 계산"

동의어 그룹 (같은 그룹 = 같은 의도 = 중복!):
  대상 ≈ 조건 ≈ 자격 ≈ 요건
  방법 ≈ 절차 ≈ 과정 ≈ 순서
  금액 ≈ 비용 ≈ 요금 ≈ 수수료
  기한 ≈ 기간 ≈ 시기 ≈ 시점
  계산 ≈ 산정 ≈ 산출
  지급 ≈ 수령 ≈ 수급
  감면 ≈ 공제 ≈ 절세
  종류 ≈ 유형 ≈ 구분
```

## ⚠️ 작업 순서 (상향식 조립 — 절대 규칙!)

```
❌ 하향식 금지: 타이틀 먼저 → 키워드 쪼개기 → H2
   → 50개 넘으면 키워드가 억지로 나옴

✅ 상향식 필수: 키워드 수집 → 타이틀 조립 → H2 생성
   → 키워드 = H2 (처음부터 동일)
   → 100개 확장해도 일관성 유지

Step 1: 키워드 4개 수집 (PAA/자동완성/생활법령/FAQ)
Step 2: 키워드 4개로 타이틀 조립
Step 3: 키워드에서 H2 질문형 생성
Step 4: description 작성

절대 Step 2 → Step 1 순서로 하지 않는다!
```

## 🎯 신규 사이트 롱테일 전략

```
신규 사이트(DA 낮음) = 2~3단어 키워드로 노출 불가!

키워드 길이 기준:
  ❌ 2단어: "퇴직금 계산" → 경쟁 높음, 노출 불가
  ❌ 3단어: "퇴직금 지급 기준" → 여전히 경쟁
  ✅ 4단어: "퇴직금 중간정산 신청 방법" → 롱테일 노출 가능
  ✅ 5단어: "퇴직금 미지급 노동청 신고 방법" → 경쟁 낮음

타이틀도 롱테일 중심:
  ❌ "퇴직금 계산 방법 — 세금과 실수령액"
  ✅ "퇴직금 중간정산 신청 방법 — 주택구입 의료비 사유별 조건"
```

## 🔄 행동 키워드 전환 규칙

```
정보형만으로 키워드 4개 채우지 않는다!
정보형이 들어오면 행동형으로 전환한다.

변환 패턴:
  "~란"/"~뜻"     → "~신청 방법" / "~계산 방법"
  "~종류"          → "~선택 방법" / "~비교 후 신청"
  "~기간"          → "~기한 내 신청" / "~연장 방법"
  "~대상"          → "~자격 조건 확인" / "~신청 자격"

예시:
  ❌ 정보형만: "원천세 뜻", "원천세 세율", "원천세 종류", "원천세 대상"
  ✅ 행동 전환: "원천세 신고 방법", "원천세 세율 계산", "원천세 납부기한", "원천세 가산세 줄이는 법"

행동 키워드 = 사용자가 뭔가 하려는 검색어:
  ~신청, ~계산, ~받는 법, ~줄이는 법, ~신고
  ~해지, ~변경, ~이전, ~전환, ~비교 후 선택
```

## 📝 Description 규칙

```
글자 수: 80~120자
패턴: "~거 아시나요?" 또는 "~방법을 알려드려요"
키워드: 타이틀 키워드 중 2개 이상 자연 배치
구조: 2문장 (호기심 유발 + 해결 제시)

✅ 좋은 예시:
"퇴직금 중간정산이 주택구입 외에도 가능하다는 거 아시나요?
 의료비·전세금 사유별 신청 조건과 방법을 알려드려요"

❌ 나쁜 예시:
"퇴직금 중간정산에 대해 알아보겠습니다" ← 호기심 없음
"퇴직금 중간정산 조건 방법 서류 비용 총정리" ← 키워드 나열
```

# 허브 (Hub)

## 허브 타이틀 전략

```
[핵심 연관검색어 3개] — [추가 연관검색어 3개]

허브 = 주제 전체를 커버하는 권위 페이지
네이버/구글 연관검색어 기반으로 6~8개 실제 검색어 커버
스포크들이 허브로 트래픽을 보내는 구조

파일 위치: src/data/hub/[슬러그].tsx
```

## 허브 H2: 의도 카테고리 기반

```
허브 H2는 스포크와 다름!
  스포크: keyword = H2 = PAA (1:1:1 엄격 매칭)
  허브: 의도 카테고리별 H2 (연관검색어 다수 커버)

의도 카테고리 (검색량 높은 순서로 배치):
  what      → ~란 뭔가요? / ~뜻
  how much  → ~세율 / ~계산 / ~금액 / ~표
  when      → ~기한 / ~언제 / ~기간
  risk      → ~가산세 / ~벌금 / ~불이익
  how       → ~신고 방법 / ~신청 / ~홈택스

순서 고정 아님! 해당 주제에서 검색량 높은 의도가 위로.
```

## 허브 예시

```yaml
title: "원천세 뜻 세율 신고 방법 — 소득별 납부기한과 가산세 계산"
slug: "원천세-세율-신고-납부기한-가산세"

추출 키워드 (6개):
  원천세 뜻           ← what
  원천세 세율         ← how much
  원천세 신고 방법    ← how
  원천세 납부기한     ← when
  원천세 가산세       ← risk
  원천세 계산         ← calc

H2 (의도 카테고리 기반):
  ## 원천세란 무엇인가요?                         ← what
  ## 소득별 원천세 세율은 얼마인가요?              ← how much
  ## 원천세 신고는 어떻게 하나요?                  ← how
  ## 원천세 납부기한은 언제까지인가요?             ← when
  ## 원천세 가산세는 얼마나 나오나요?              ← risk
  (+ 소득별 세부 섹션: 근로/사업/기타/퇴직/연금/금융)
```

# 스포크 (Spoke)

## 스포크 타이틀 전략

```
[메인 롱테일 키워드] — [추가 롱테일 자연 배치]

스포크 = 허브의 세부 주제 1개를 깊게 다루는 글
keyword 4개, 1:1:1 엄격 매칭 (keyword = H2 = PAA)

— 뒤쪽도 구체적 행동!
  ❌ "~ — 관할법원 확인"
  ✅ "~ — 관할법원 선택과 비용 계산"

파일 위치: src/data/spoke/[슬러그].tsx
```

## 스포크 Keywords 규칙

```
정확히 4개
실제 사람이 검색창에 치는 말! (볼륨 낮아도 OK)
타이틀에서 자연스럽게 추출 가능해야 함
최소 3단어, 권장 4~5단어 롱테일 (신규 사이트 기준)

★ 핵심: keyword = H2 = PAA (1:1:1 매칭!)
★ 4개 키워드 = 4개 다른 검색 의도! (동의어 금지!)
★ 정보형 2개 이하 + 행동형 2개 이상 권장!

나쁜 키워드:
  ❌ "원천세 납부처" (아무도 이렇게 안 검색)
  ❌ "홈택스 이용법" (부자연)
  ❌ "종합소득세 신고" + "종합소득세 신고 방법" (동의어)
  ❌ "퇴직금 계산" (2단어, 신규 사이트 노출 불가)
```

## 스포크 H2 규칙 (PAA 질문형)

```
모든 H2 = 질문형 (~나요?, ~하나요?, ~있나요?)
모든 H2에 베이스 키워드 포함
keyword → H2 변환이 1:1로 자연스럽게!
```

## 스포크 모범 예시

### 기준 예시 (신규 사이트용 롱테일)
```yaml
title: "주택청약 가점제 점수 계산 방법 — 무주택 기간 산정과 부양가족 인정 범위"

keyword 1: 주택청약 가점제 점수 계산    → how       → ## 주택청약 가점제 점수는 어떻게 계산하나요?
keyword 2: 청약 무주택 기간 산정 기준   → factor 1  → ## 청약 무주택 기간은 어떻게 산정되나요?
keyword 3: 청약 부양가족 인정 범위      → factor 2  → ## 청약 부양가족 인정 범위는 어떻게 되나요?
keyword 4: 청약 가점 만점 받는 법       → action    → ## 청약 가점 만점 받는 법은 뭔가요?

description: "주택청약 가점제에서 무주택 기간이 배우자 기준으로
산정된다는 거 아시나요? 점수 계산 방법과 부양가족 인정 범위,
만점 받는 전략을 알려드려요"
```

## 안전한 키워드 추출 방법 (필수!)

### 가짜 키워드 생성 절대 금지 ⚠️

```
❌ 상상으로 만든 키워드 = 검색량 0 = 트래픽 0
✅ 실제 검증된 키워드 = 실제 검색량 = 트래픽 유입
```

### WebFetch 우선 검증 프로세스

```yaml
단계1_URL수집:
  - 사용자가 정부/공식 사이트 URL 제공
  - 생활법률, 100문100답, 정부24 등

단계2_WebFetch검증:
  - WebFetch로 실제 페이지 내용 확인
  - H2, H3, 질문 목록 추출
  - 실제 존재하는 키워드만 수집

단계3_중복제거:
  - src/data/spoke/ 검색
  - src/data/hub/ 검색
  - content/wiki/ 검색
  - 기존 글 있으면 "수정" 표시
  - 없으면 "신규" 표시

단계4_확장반복:
  - 사용자가 추가 URL 제공
  - 단계2~3 반복
  - 중복 자동 필터링
```

### 키워드 소스 우선순위

```
허브 (6~8개): 네이버 연관검색어 > 구글 PAA > 네이버 자동완성 > 구글 자동완성
스포크 (4개): 생활법률 H2/H3 > 100문100답 > 정부 사이트 FAQ > 네이버 지식iN
```

## 허브 분리 전략 (스포크 20개 이상 시 필수!)

### 허브당 스포크 개수 기준
```yaml
이상적: 1개 허브 = 10~15개 스포크 (SEO 최적)
한계: 1개 허브 = 최대 20개 스포크
경고: 30개 이상 → 반드시 허브 분리!
```

### 허브 분리 기준

| 스포크 개수 | 허브 개수 | 전략 |
|------------|----------|------|
| 1~15개 | 1개 | 단일 허브로 충분 |
| 16~20개 | 1개 | 단일 허브 유지 (최대) |
| 21~30개 | 2~3개 | 주제별 or 단계별 분리 |
| 31~50개 | 3~5개 | 주제별 분리 필수 |
| 51개 이상 | 5개+ | 세분화된 허브 구조 |

### 분리 방식

**옵션 A: 주제별 분리 (추천)**

## 5. 시각 배치 규칙

키워드 세트 생성 시 각 스포크에 섹션별 시각 요소를 지정한다.
에이전트는 지정된 시각을 그대로 사용하고, 임의 변경하지 않는다.

### 형식
```
Spoke N: {제목}
  visuals:
    S1: {시각A} + {시각B}
    S2: {시각C} + {시각D}
    S3: {시각E} + {시각F}
    S4: {시각G} + {시각H}
  종류: {N}종 ✅ | 연속: 없음 ✅
```

### 배치 제약
- 같은 허브 내 8개 스포크의 시각 조합이 완전히 같으면 안 됨
- 섹션 간 같은 시각 요소 연속 사용 금지
- 4종류 이상 사용
- SpokeTable은 스포크당 최대 2개
