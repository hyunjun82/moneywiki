# 허브 작성 에이전트 (Hub Writer)

> Claude Code가 허브 TSX 파일을 작성할 때 따르는 단계별 지침.
> 반드시 `hub-rules.md` + `hub-template.md` + `hub-golden-example.tsx`를 먼저 읽은 후 시작.

---

## 작업 흐름 — 7단계

### Step 1. 참조 파일 읽기 + 기존 스포크 확인

```
필수 읽기:
1. hub-rules.md (원칙)
2. hub-template.md (코드 구조)
3. hub-golden-example.tsx (완성 예시)
4. critical-facts.yaml (사실 검증 기준)

스포크 확인:
5. CSV에서 해당 허브의 스포크 슬러그 전부 확인
6. src/data/spoke/ 폴더에서 해당 스포크 파일 존재 여부 확인
7. 존재하는 스포크 파일을 읽고 — 서론 패턴, 시각 컴포넌트 조합, 톤 확인
   → 허브에서 동일한 문장/구조 사용 금지
```

### Step 2. 검색 + 출처 확보

```
1순위: 정부·공공기관 WebFetch
       (법원 scourt.go.kr, 법률구조공단 klac.or.kr, 국세청 nts.go.kr 등)
2순위: 대형 금융사이트 자체 도메인
       (toss.im, kbfg.com 등 — 블로그 제외)

금지: 네이버블로그, 티스토리, 위키백과, 개인블로그, 카페

검색 규칙:
- WebSearch 2~3회로 핵심 수치·날짜 확보
- 숫자 데이터는 출처 확인 후에만 기재
- 출처에서 확인 불가한 숫자는 "약" 또는 "근사치" 표기
- 대형사 블로그(blog.xxx.com) = 블로그 → 금지
```

### Step 3. spokeGrid 작성

```
CSV에서 해당 허브의 스포크를 전부 추출:

spokeGrid 작성 규칙:
- 순서: 사용자 여정 순 (기초 개념 → 실행 → 비용 → 지원/후속)
- badge: 2~3글자 (자격, 절차, 서류, 비용, 비교, 지원 등)
- title: 스포크 h1과 동일하거나 축약
- desc: 1줄 ~예요체
- href: /w/ + 스포크 슬러그

체크:
□ CSV의 스포크 수 = spokeGrid 항목 수 (누락 없음)
□ 순서가 자연스러운 여정인가?
□ badge가 서로 겹치지 않나?
```

### Step 4. hero + quickAnswer 작성

```
hero.h1:
- CSV의 "타이틀" 기반
- <br/> + <strong>으로 2줄 구성

hero.intro:
- 2단락, ~예요체
- 1단락: 주제 정의 + 핵심 정보
- 2단락: 이 글에서 다루는 범위

hero.quickAnswer:
- title: "핵심 요약" (고정)
- body: H2-1의 핵심 답변 3줄 이내 + 구체 숫자 1개 이상
- hook: spokeGrid 또는 본문으로 유도하는 자연스러운 한 줄

서론 금지 표현:
❌ "알아보겠습니다" / "살펴보겠습니다"
❌ "많은 분들이 궁금해하시는"
❌ "이번 포스팅에서는"
❌ "~란 무엇일까요?"
❌ "오늘은 ~해보려고 합니다"
❌ "궁금한 부분부터 골라 읽어도 돼요" (hubCTA 버튼용, 서론 안 됨)
❌ "그래서 직접 정리했어요" (주체 애매)
```

### Step 5. sections 작성 (H2 본문)

```
H2 텍스트: CSV의 H2-1 ~ H2-4 그대로 사용

각 섹션 구조:
1. 요약 단락 2~3개 (~예요체)
2. 시각 컴포넌트 0~1개 (선택)
3. 스포크 유도 링크 1~2개 (마지막 단락)

허브 sections 핵심 원칙:
- 깊이: 개요 수준만. "자세한 내용은 스포크에서" 유도
- 단락 길이: 각 단락 2~4문장 (5줄 이상 금지)
- 시각: SpokeTable, SpokeCompareCards 위주 (가볍게)
- BridgeCTA: 절대 사용 금지

전환 패턴 (H2 간):
A. "신청 자격을 확인했으니, 이제 실제 절차를 볼게요."
B. "비용은 인지대 + 예납금으로 구성돼요."

전환 금지:
❌ "그럼 이번에는 ~에 대해 알아볼까요?"
❌ "다음으로 ~를 살펴보겠습니다"

스포크 유도 링크 형식:
<a href="/w/스포크-슬러그" className="text-emerald-600 font-semibold hover:underline">
  스포크 제목
</a>

마지막 section은 반드시:
{ heading: null, content: null }  → FAQ 자동 삽입
```

### Step 6. faq + sources 작성

```
faq 규칙:
- 3~5개 (허브 전체를 아우르는 넓은 질문)
- ~예요체 필수 (예외 없음)
- answer: 2~3문장
- 스포크 FAQ와 겹치지 않는 질문 선택
- "~인가요?" 질문 → "~예요." 답변 패턴

sources 규칙:
- 최소 2개
- 정부/공식 사이트 우선
- url은 실제 접근 가능한 주소
```

### Step 7. 품질 자가 검증

작성 완료 후 아래 항목을 모두 확인:

```
## 구조 검증
□ spokeGrid에 CSV의 해당 허브 스포크가 전부 포함됐나?
□ H2가 3~4개이고 CSV의 H2-1~H2-4와 일치하나?
□ 마지막 section이 { heading: null, content: null }인가?
□ BridgeCTA를 사용하지 않았나?

## 콘텐츠 검증
□ quickAnswer에 구체 숫자 1개 이상 있나?
□ 각 H2 끝에 스포크 링크가 1~2개 있나?
□ 시각 컴포넌트가 2~4개인가?
□ 스포크와 동일한 문장이 없나?
□ 숫자 데이터에 출처가 있나?

## 톤 검증
□ 모든 텍스트가 ~예요체인가? (FAQ answer 포함)
□ 서론에 금지 표현(알아보겠습니다 등)이 없나?
□ 문어체 종결어미(~습니다/~됩니다)가 없나?
□ 5줄 이상 단락이 없나?

## 메타 검증
□ meta.description이 150자 이내인가?
□ meta.keywords가 4개인가?
□ badge에 연도 표기가 있나?
□ sources에 정부/공식 사이트 2개 이상인가?

## 즉시 경고 패턴
⚠️ 아래 발견 시 즉시 수정:
- "~습니다" → "~예요" / "~돼요"
- "~됩니다" → "~돼요"
- "알아보겠습니다" → 삭제 후 재작성
- "살펴보겠습니다" → 삭제 후 재작성
- BridgeCTA 사용 → 삭제
- spokeGrid 누락 → CSV 재확인 후 추가
```

## 파일 생성 + 등록

```
1. src/data/hub/[슬러그].tsx 파일 생성
2. src/data/hub/registry.ts에 import + 등록 추가
3. verify-spoke-quality.js 통과 확인 (hub도 동일 검증)
4. prettier 포맷 확인
5. tsc --noEmit 타입 확인
```

## 허브 vs 스포크 에이전트 차이 요약

| 항목 | spoke-writer | hub-writer (이 파일) |
|------|-------------|---------------------|
| H2 개수 | 4~6개 | 3~4개 |
| H2 깊이 | 5~8단락 | 2~3단락 |
| 시각 컴포넌트 | 4종+ 필수 | 2~4개 (가볍게) |
| BridgeCTA | 있음 (허브로 유도) | 없음 (자기가 허브) |
| spokeGrid | 없음 | 있음 (핵심 요소) |
| hubCTA | 있음 | 없음 |
| 스포크 링크 | relatedSpokes 2~4개 | 매 H2 끝에 1~2개 |
| FAQ 수 | 2~4개 | 3~5개 |
| 내부링크 방향 | ← 허브로 돌려보냄 | → 스포크로 보냄 |
