# 머니위키 금시세·환율 개편 실행 스펙

저장소: `hyunjun82/moneywiki` · 데이터 브랜치: `price-data` · 배포: Cloudflare Pages (main)
작성 기준: 2026-09-09 실측. 아래 순서대로 진행한다. 1~4는 코드 몇 줄이라 하루 안에 끝나고, 5부터가 본 작업이다.

## 0. 현재 구조 (확인된 것)

- 사이트는 `raw.githubusercontent.com/hyunjun82/moneywiki/price-data/fx.json`을 클라이언트에서 읽는다. 금 데이터도 같은 방식이거나 서버 fetch.
- GitHub Actions 크론이 환율은 매시, 금은 5~6시간마다 `[CI Skip]` 커밋. 리빌드 없음. 이 구조는 유지한다.
- 뉴스 기사는 main 브랜치에 `feat: 금시세 뉴스 YYYY-MM-DD` 커밋 → 프로덕션 배포. 현재 08시경 생성.
- fx 소스: Yahoo Finance 중간환율. 은행 우대율: 은행연합회 외환길잡이 (5일 지연).
- 금 소매 소스: 종로금거래소 (부가세 별도 고시). 도매: 공공데이터포털 KRX (1~2일 지연).
- **한국금거래소는 HTML 스크래핑이 아니라 JSON API가 있다** (5절). 단, **해외 IP는 403** (AWS WAF). GitHub Actions 러너(미국)에서 호출하면 실패한다. 수집기는 국내 IP에서 돌려야 한다 → quiz.jjyu에서 이미 쓰는 **Cowork 예약 작업(PC 실행 → 커밋 push)** 패턴을 그대로 쓴다.

## 1. `fx.json` 등락률을 전일 대비로 (즉시 · 환율 페이지 + 뉴스 기사 오류 동시 해결)

**증상** USD ▼22.11(−1.63%), JPY ▲14.90(+1.74%)로 표시. 실제 전일 대비는 USD −7.29(−0.54%), JPY **−3.64(−0.42%)**. 엔화는 내렸는데 빨간 ▲로 나온다. 원인은 `change = rate − history[0].rate` (6일 전 대비).

**수정** 수집 스크립트에서:

```js
// history는 날짜 오름차순, 마지막이 오늘일 수도 아닐 수도 있음
const prev = [...history].reverse().find(h => h.date < historyDate);
const change    = prev ? +(rate - prev.rate).toFixed(2) : 0;
const changePct = prev ? +((rate / prev.rate - 1) * 100).toFixed(2) : 0;
```

**같이 추가** `changeBasis: "prevClose"`, `prevClose: {date, rate}` 필드. 화면에 "전일 대비"라고 명시.

**검증** 9/9 기준 USD change가 −7.29, JPY가 −3.64로 나오면 통과.

## 2. 살 때 가격을 부가세 포함으로 전 페이지 통일 (즉시)

**증상** `/gold` 살 때 756,000원 = 종로 고시(부가세 별도). 실제 결제액 831,600원. `/gold/sell`의 "살 때 대비 −51,000원 (6.7%)"도 이 값으로 계산돼 틀림. 실제는 126,000원(15.2%). 뉴스 기사 본문은 이미 127,500원이라고 맞게 쓰고 있어서 페이지끼리 모순.

**수정** 데이터 레이어에서 `buy`는 항상 부가세 포함 값으로 저장. 종로 소스를 쓰는 동안은 `buyExVat × 1.1`을 `buy`로, 원본은 `buyExVat`로 따로 보관. 화면에는 `buy`만 노출하고 "VAT 포함" 표기.

**같이 수정** 등락률 분모를 전일 고시로. 현재 `9,000 / 705,000 = 1.29%` → `9,000 / 714,000 = 1.26%`.

## 3. 뉴스 기사 생성 시각 (즉시)

**증상** 08시 생성 → 한국금거래소 당일 고시(10시경) 전이라 전일 숫자가 오늘 기사에 들어감.

**수정** 크론을 **평일 10:15 KST**로 (UTC `15 1 * * 1-5`). 실측상 한국금거래소 1차 고시는 09:53(9/9)이었다. 실행 시 `gold.json.retail.quotes[0].date`가 오늘인지 확인하고, 아니면 10:45·11:15에 재시도. 셋 다 실패하면 발행하지 않고 알림.

## 4. 금 수집 주기 (즉시)

**증상** 5~6시간 간격이라 하루 2~5회 나오는 고시 회차를 놓친다.

**수정** 한국금거래소 수집: 평일 09:30~18:30 30분마다, **PC의 Cowork 예약 작업**으로 (GitHub Actions 불가, 0절 참고). API 한 번 호출에 금·18K·14K·백금·은이 전부 오므로 금속별 호출이 필요 없다. 응답의 최신 `date`가 저장된 값과 같으면 커밋하지 않는다.

## 5. `gold.json` 신설 (핵심 · 소매 소스 교체 + 기준가 자체 계산)

**소스 변경** 종로금거래소 → **한국금거래소 JSON API**. 웹 테이블을 긁지 않는다.

```
POST https://www.koreagoldx.co.kr/api/price/chart/list
Content-Type: application/json
Accept: application/json
X-Requested-With: XMLHttpRequest
Referer: https://www.koreagoldx.co.kr/price/gold

{"srchDt":"SEARCH","type":"Au","dataDateStart":"2026.09.01","dataDateEnd":"2026.09.09"}
```

응답 `{"list":[...]}` — 최신순, 한 행이 고시 1회. 필드 매핑:

| API 필드 | 뜻 | 9/9 11:19:25 값 |
|---|---|---|
| `date` | 고시 시각 (초 단위) | `"2026-09-09 11:19:25"` |
| `s_pure` / `p_pure` | 순금 살 때 / 팔 때 (VAT 포함) | 831000 / 705000 |
| `p_18k` / `p_14k` | 18K / 14K 팔 때 | 518200 / 401900 |
| `s_18k` / `s_14k` | 18K / 14K 살 때 (웹엔 "제품시세적용"으로 숨김) | 610785 / 473670 |
| `s_white` / `p_white` | 백금 살 / 팔 | 344000 / 279000 |
| `s_silver` / `p_silver` | 은 살 / 팔 | 11960 / 9950 |

- 날짜 형식은 점 구분 `YYYY.MM.DD`. 기본 화면이 5개월치를 한 번에 받으므로 `dataDateStart`를 넓혀 **이력 백필도 이 호출 하나로** 끝난다 (1년 범위 허용 여부는 첫 실행 때 확인).
- **해외 IP 403.** 이 샌드박스와 GitHub Actions 러너에서는 실패한다. 수집 스크립트는 사용자 PC의 Cowork 예약 작업으로 실행하고 결과만 `price-data`에 push한다. Cloudflare Worker(국내 POP)로 되는지는 별도 테스트.
- `s_18k`/`s_14k`는 API에만 있는 값이라 표시 여부는 선택. 표시한다면 "제품 시세 참고값"으로.

**기준가는 스크래핑하지 않고 계산한다.** KB 골드뱅킹은 robots `Disallow: /`. 대신 KB와 동일한 공식으로 직접 계산. 이미 있는 Yahoo XAU/USD와 USD/KRW를 쓰면 추가 호출이 없다. 9/9 14:44 검증: `4395.59 / 31.1034768 × 1336.80 × 3.75 = 708,445` (KB 고시 708,445와 일치).

**스키마**

## 6. `fx.json` 이력 1년 백필 + 공식 매매기준율

- **history 백필** 현재 5일치뿐이라 1개월·6개월·1년 탭이 전부 1주를 그린다. 한국수출입은행 API `searchdate`로 365일 루프 1회 실행 후 매일 append. `https://oapi.koreaexim.go.kr/site/program/financial/exchangeJSON?authkey=KEY&searchdate=YYYYMMDD&data=AP01` (무료, 인증키 필요, 영업일 11시 갱신, 1,000회/일).
- **official 채우기** 지금 `official: null`. 수출입은행 매매기준율·송금 보내실 때·받으실 때를 넣고 화면에 "은행 고시 매매기준율"로 표시. Yahoo 값은 "시장 중간환율"로 구분.
- **은행 우대율** 5일 지연 → 매일 갱신으로.
- **현찰 살 때·팔 때는 스크래핑하지 않고 계산한다.** KB·네이버금융은 robots 차단. 대신 이미 있는 은행연합회 `feeRate`로:
  `현찰 살 때 = 기준율 × (1 + feeRate/100 × (1 − 우대율/100))`, `현찰 팔 때 = 기준율 × (1 − feeRate/100 × (1 − 우대율/100))`.
  검증: KB 9/8 10:28 기준율 1,338.20 × 1.0175 = 1,361.62 (KB 고시 1,361.61). 기준율은 수출입은행 official을 쓰고, 장중 지표로만 Yahoo를 쓴다.

## 7. 페이지 (main 브랜치)

### `/gold` 허브 — 목업 v2 구조 그대로
보드(살 때·팔 때·스프레드 브래킷) → 7일 스파크 → [기간별 등락 · 831,000원 분해 · 기준가] → 차트(1주/5개월, 1개월·1년은 이력 쌓이면 활성) → 시세표(1돈/1g/1kg) + 고시 이력 3일 → 간이 계산기 → FAQ. 각 섹션에 스포크 링크. 타이틀: `오늘의 금시세 | 순금 1돈 살 때 팔 때 · 18K 14K 매입가 · 한국거래소 기준가`

### `/gold/sell` — 팔 때 전용
타이틀 `금 팔때 시세 | 오늘 순금·18K·14K 매입가와 실수령액`. 순도별 전체(24K·22K·18K·14K·10K) + 매입률(지금 있는 98.0%·97.4% 유지) + **정액 차감 분석**(함량 이론가 − 실제 = 약 10,550원 정액) + 감량·알 제외·도금 규칙 + 업체 2~3곳 매입가 비교 + 팔 때 계산기(감량율 입력). 이 페이지가 "돌반지 팔까" 검색자의 착지점.

### `/gold/buy` — 살 때 전용
타이틀 `금 살때 가격 | 골드바 시세와 순금 1돈 구매가 (VAT 포함)`. 831,000원 분해 상세 + 골드바 중량별(1g·3.75g·10g·37.5g·100g·1kg) + **금방 vs 골드뱅킹 vs KRX 금현물 비교표**(수수료·세금·실물 여부) + "사자마자 팔면 15.2%" 경고.

### `/gold/silver` — 신설
타이틀 `오늘 은시세 | 은 1돈 살 때 팔 때 · 실버바 1kg 가격`. "오늘은시세" 문서 528개뿐인 자리. 은 보드 + 은 스프레드(9/9 16.75%, 금 14.86%보다 큼) + 실버바 kg 환산(살 3,184,000 / 팔 2,650,667) + 은수저·실버바 매입 규칙 + 국제 은 XAG/USD.

### `/gold/calculator` — 확장
여러 품목 합산(24K 3돈 + 18K 2돈 + 14K 1돈), 감량율 %, 수수료, 결과 공유 URL. 백금·은 포함.

### `/gold/news/YYYY-MM-DD` — 템플릿 교체
데이터 나열 → 기사체 5~6섹션: 도입(문제정의) → ① 한국거래소 기준가 대비 → ② 살 때 분해 → ③ 18K·14K 정액 차감 → ④ 오늘 은시세 → ⑤ 내린/오른 이유 → 행동. 표·볼드 최소. 공백 포함 2,500자 내외. 숫자는 전부 `gold.json`·`fx.json`에서 가져오고 본문에서 재계산하지 않는다.

## 9. 환율 페이지 (main 브랜치)

### 구조
```
/fx                허브 — 오늘 환율 전체 고시표 (매매기준율·현찰 살/팔) + 간이 계산기
/fx/jpy            엔화 환율 전용 (확정 · 736만)
/fx/usd            달러 환율 전용 (확정 · 464만)
/fx/eur /fx/cny    검색량 확인 후
/fx/vnd /fx/thb /fx/php  검색량 확인 후 (블랙키위 6개 뽑아 순위로 결정)
/fx/banks          은행별 환전 비교 (있음) — 통화 선택 추가
/fx/calculator     환율 계산기 (지금 /fx 타이틀 키워드 유지용으로 분리)
/fx/news/YYYY-MM-DD  일별 기사
```
확정 2개(jpy·usd)부터 만들고, 나머지는 검색량 순위대로 하나씩. 얇은 페이지를 한꺼번에 만들지 않는다.

### 허브 `/fx`
타이틀 `오늘 환율 | 달러 엔화 유로 위안 매매기준율·현찰 살 때 팔 때`. 히어로 카피 삭제. 첫 화면 = LIVE 티커 + 주요 6통화 큰 숫자(전일 대비) + 갱신 시각. 아래 17통화 고시표에 **현찰 살/팔 열 추가**(6절 계산식). 간이 계산기. 각 통화 행에서 전용 페이지로 링크.

### 통화 전용 `/fx/jpy` (usd 등 동일 템플릿)
타이틀 `엔화 환율 | 오늘 100엔 살 때 팔 때 · 은행별 환전 우대율 비교`.
1. 보드: 100엔 매매기준율 큰 숫자 + 전일 대비(전일 종가 분모) + 갱신 시각 + 현찰 살 때/팔 때 (계산값, "우대 0% 기준")
2. 기간별 등락: 오늘 / 1주 / 1개월 / 3개월 / 1년 (6절 백필 전까지는 있는 구간만)
